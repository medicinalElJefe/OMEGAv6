# R349 Hardware Woven Field

R349 moves the already-established R315/R348 calculus into a hardware-aware full-field execution path without changing truth or dispatch authority.

## Executable path

1. **Partition** — 20,736 canonical addresses are divided into deterministic bounded ranges from browser-returned scheduling hints.
2. **Exchange / transport** — the typed invariant field undergoes bounded conservative directional address-neighbor transport.
3. **Invariant carry** — before/after totals and numerical residual are measured.
4. **Scar / history carry** — transport delta accumulates into the typed scar channel; motion carries the observed software-state change.
5. **Orientation / frame re-expression** — signed orientation remains a separate channel from structure.
6. **Recontextualize / repartition** — invariant state can be conservatively projected only to declared 12^k address resolutions.
7. **Prove** — coverage and residual receipts remain explicit.
8. **Render** — the canonical 20,736 addresses map exactly to a 144×144 RGBA raster: pixel index equals canonical address.

## Hardware / display boundary

Browser `hardwareConcurrency`, `deviceMemory`, Worker availability and device-pixel ratio are hints for execution/render planning. They are not proof of physical compute throughput, device identity, scientific validity or native Hybrid execution. The Web Worker moves full-field calculation off the UI thread when available; a deterministic fallback remains available.
