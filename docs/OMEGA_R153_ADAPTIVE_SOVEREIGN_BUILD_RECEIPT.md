# OMEGA R153 — Adaptive Sovereign Build Missions

R153 is based on current `main` after the R152 optical/RCWA operational convergence. It preserves that R152 line and upgrades the authenticated R151 PC build surface from one-cycle mission admission into a bounded returned-proof lifecycle.

Execution path:

`CURRENT AUTHENTICATED HEARTBEAT -> DISCOVERY -> PROJECT PROOF -> NODE PREFLIGHT WHEN REQUIRED -> BUILD/TEST -> RETURNED FAILURE EVIDENCE -> BOUNDED READ PREIMAGE -> EXACT SHA-BOUND PATCH PROPOSAL -> REBUILD/RETEST -> PACKAGE + SUPPORT BUNDLE -> COMPLETE`

Core laws:

- No queue state, browser state, or model output is execution proof.
- Only the authenticated R132 host performs allow-listed native operations inside the approved root.
- Broad-root runs discover before mutation.
- Node projects prove declared build/check/test scripts before adaptive continuation.
- Repairs target only source paths named by returned failure evidence.
- Every mutation is an exact replacement bound to the SHA-256 of a returned READ_TEXT preimage.
- Workers AI may propose a patch but cannot bypass path, preimage, replacement-count, operation-envelope, device-capability, or cycle validation.
- The R153 full-build envelope is hard-capped at 12 cycles and at most two repair attempts. This is sufficient for discovery, preflight, two bounded repair loops and final packaging without unbounded autonomy.
- PACKAGE and SUPPORT_BUNDLE occur only after a returned successful build/test cycle.
- COMPLETE is written only after the package job itself returns successfully.
- R141 remains Hybrid returned-proof closure, R147 remains unified executor evidence, R125 remains CanonState admission authority, and current R152 optical/RCWA services remain preserved.
- R153 extends the existing R116 Durable Object. It does not create a shadow Worker or a second canonical runtime.

The existing R151 Sovereign full-build control remains the operator surface. A narrow compatibility mount maps that established UI/Worker contract into the R153 lifecycle so the currently paired PC does not need to be re-paired simply because the mission engine advanced.
