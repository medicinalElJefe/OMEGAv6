# OMEGA7 Foundation

OMEGA7 is a controlled successor reconstruction over the proven OMEGAv6 capability core. It is not a rewrite of the engines and it does not retire OMEGAv6 during migration.

## Non-negotiable inheritance rule

No OMEGAv6 capability is retired until OMEGA7 proves equivalent-or-better inheritance for that capability.

Current foundation census:
- 44 canonical OMEGAv6 routes inherited
- 44 unique OMEGA7 capability IDs
- 6 human-facing presentation domains
- one compatibility bridge back to current OMEGAv6 execution surfaces
- one OMEGA7 global shell state authority
- one bounded error/failure presentation contract
- progressive disclosure: Standard / Advanced / Canon

## Layer model

1. **Proven OMEGAv6 capability core**
   - CanonState / R125 admission
   - R436 canonical domain resolution
   - route/capability authority
   - Earth/weather
   - traversal/motion
   - spectral/color
   - science/atomic source gates
   - Hybrid/device execution
   - CLOUD-01/self-development
   - evidence/proof
   - memory/archive
   - project/create/render/build/system families

2. **OMEGA7 capability inheritance registry**
   - stable OMEGA7 capability ID
   - exact OMEGAv6 legacy route identity
   - human label and description
   - family
   - source/evidence boundary
   - current runtime reality
   - human-facing domain
   - compatibility route

3. **OMEGA7 application state authority**
   - current human domain
   - presentation depth
   - selected capability
   - command search state
   - system-status state
   - runtime health summary

   Canonical scientific/runtime state remains owned by its existing OMEGA authorities. UI state cannot promote truth or CanonState.

4. **OMEGA7 product shell**
   - one top bar
   - one primary navigation system
   - one main scroll owner
   - one command/search palette
   - one system status surface
   - one responsive mobile navigation system

5. **Compatibility execution bridge**
   - OMEGA7 presentation may launch any current OMEGAv6 capability.
   - Until a capability is migrated into a native OMEGA7 workspace, execution remains delegated to the accepted OMEGAv6 surface.
   - This makes migration additive and prevents feature loss.

## Human presentation

OMEGA7 presents six top-level domains:

- Home
- Work
- Explore
- Create
- Develop
- System

The complete 44-capability inventory remains searchable and reachable. The six-domain model is a presentation projection, not a capability reduction.

## Progressive disclosure

### Standard
Human terminology, task-first cards, readiness, results, next actions.

### Advanced
Family, authority, source boundary, execution state, alternatives, evidence.

### Canon
Full OMEGA terminology, exact route identity, state/address details, proof/ledger context, calculus/modes.

The three presentations must remain projections of the same authoritative state.

## Reliability rules

OMEGA7 must not ship a user-facing capability that lacks:

- loading state
- ready state
- running state when applicable
- success/result state
- unavailable/degraded/held state
- failure state
- recovery action
- mobile layout
- keyboard path for primary actions
- proof of capability inheritance

A capability exception is contained by the OMEGA7 boundary and may not collapse the product shell.

Unknown external/cloud/device health is reported as UNKNOWN until observed. OMEGA7 must not convert absence of observation into READY or FAILED.

## Migration states

Future native OMEGA7 capability adapters should move through:

BRIDGED -> ADAPTED -> PARITY_PROVED -> NATIVE -> LEGACY_RETIRED

LEGACY_RETIRED is forbidden unless parity proof is current and rollback remains available.

## Activation

As of the R454 cutover candidate, OMEGA7 is the default product shell after accepted full-product parity.

Explicit selection remains reversible:

- `?omega7=1` forces OMEGA7
- `?omega6=1` forces OMEGAv6
- the product-shell preference is stored in `omega.product.shell`

OMEGAv6 remains intact as the explicit rollback product. R454 changes startup preference only; it does not delete or retire the accepted OMEGAv6 surfaces.

## Release gates before OMEGA7 becomes default

1. 44/44 capability inheritance accounted for.
2. No primary control without an observable result or explicit held state.
3. No unhandled route exceptions.
4. Desktop and mobile navigation pass.
5. All user-facing surfaces preserve scroll and viewport ownership.
6. Provider/device failures remain contained.
7. R125, R436, exact-head promotion, deployment, and execution-proof authorities remain unchanged.
8. Browser user-journey tests pass for each native OMEGA7 workspace family.
9. Performance budgets pass.
10. Rollback to current OMEGAv6 remains immediate.

OMEGA7 is complete only when the new product experience is simpler than OMEGAv6 while preserving or improving the full accepted capability set.
