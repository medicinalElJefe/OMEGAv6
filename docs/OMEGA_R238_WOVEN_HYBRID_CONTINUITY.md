## Woven continuity law

`partition → exchange/transform → invariant carry → scar/history carry → re-contextualize/repartition`

Applied to Hybrid execution:

1. **Partition** — one authenticated selected host, one approved root, its jobs and its missions define the current local software frame.
2. **Exchange / transform** — operator intent can become a bounded R237 job or mission action only inside that selected-host frame and only from a current shared observation epoch.
3. **Invariant carry** — device identity, snapshot epoch, advertised capabilities, root confinement and the R141/R146/R147/R125 authority boundaries survive the transformation.
4. **Scar / history carry** — returned selected-host step proofs and deterministic fingerprints remain attached to that host and are not mixed with another host's history.
5. **Re-contextualize / repartition** — explicitly selecting another authenticated host changes the local frame while preserving prior receipts and isolating foreign active missions and returns.

## Orientation is separate from structure

The same selected-host continuity structure supports three declared directional roles:

- `+1` — operator / dispatcher → host
- `0` — read-only observation of the shared snapshot
- `-1` — host → returned proof / history

The sign is a directional role, not a truth score and not a new authority.

## Frame-relative roles

Whole/part and inner/outer are contextual:

- **whole:** current Hybrid operational frame;
- **part:** selected authenticated host;
- **inner:** selected host's current mission, job, returned resource profile and returned effects;
- **outer:** other authenticated hosts, foreign missions and foreign return history.

Changing host selection re-contextualizes these roles; it does not rewrite prior receipts.
