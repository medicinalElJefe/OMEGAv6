# R288 · Archive Genome Promotion Ledger

R288 converts the connected Drive corpus from an informal recovery source into a typed OMEGAv6 upgrade ledger.

## Release boundary

R288 is governance/source-data only. It does **not** promote archive donors into production execution, change canonical state authority, modify SAR/Earth truth rules, enable medical/clinical claims, or grant host/device authority.

Archive presence is evidence that an artifact exists in the reviewed corpus. It is not execution proof, scientific validation, medical validation, authorship proof, or production admission.

## Master operation

`PRUNE → FINGERPRINT → ORIGIN → MAP → DIFF → RECOVER/ADAPT → TEST → PROVE → PROMOTE → RE-ARCHIVE`

This extends the established PRUNE → TRANSLATE → PROVE discipline by adding archive-specific origin, fingerprint, delta and supersession stages.

## R288 registries

The long-term Archive Capability Compiler should maintain at least these registries:

1. **Artifact registry** — identity, hash, Drive/GitHub location, version/lineage, format and origin.
2. **Capability registry** — exact executable or intended capability, inputs, outputs, authority and runtime coverage.
3. **Math/mode registry** — formulas, operators, state variables, resolution/address semantics and mode bindings.
4. **Visual grammar registry** — geometry, layers, animation, controls, labels and state/evidence bindings.
5. **Proof/release registry** — manifests, tests, receipts, acceptance bundles, continuity records and supersession.
6. **Dependency registry** — third-party libraries, binaries, models, versions, licenses and hardware/runtime constraints.

## Highest-priority convergence families

### SAI / PSC

The Drive corpus contains a five-part SAI B059 distribution: compiled core, PSC atlas, PSC operator/QR, calculus/graph/proof and workbook packs. OMEGAv6 already has SAI/PSC runtime surfaces, so R288 classifies this as **PARTIAL / RECOVER_EXECUTOR**, not a greenfield build.

Primary objective: expand and fingerprint the five archives, compare their internal hashes and operator schemas to `saiB059Runtime`, and recover only unique deterministic capability under the current state/proof authority.

### Water Geometry / Mode188

The archive contains large Water force, trigonometry, scar and Mode188 state-space workbooks while OMEGAv6 currently carries a smaller Water/Woven operator in R265/R266.

Primary objective: build a formula registry and replay harness, then recover only operators that preserve current semantic guardrails. Water Geometry remains a mathematical/software transform family and is not a new physical primitive.

### Violet Transfiguration

OMEGAv6 already executes bounded Violet re-expression through `violetCanon`, R265/R266 and traversal surfaces. Drive contains a larger atlas, empirical-labeled workbooks and a historical validated-release folder.

Primary objective: formula-by-formula diff and provenance recovery. Historical `Validated` naming is not current scientific validation.

### Dimensional / Parent / Fold / Atomic Relativity

Drive contains parent-relativity charts, full-mode bridge workbooks, a fold-scale calibration harness, atomic first-hand atlases, Atomic Woven Continuity and full dimensional-relativity atlases.

Primary objective: recover calibration, parent/fold/atomic sub-engines without creating a competing coordinate authority. The hierarchy `12 → 144 → 1728 → 20,736 → 248,832` remains representational/address resolution, not literal physical dimensions.

### Heavy Bio

The 36-shard Heavy Bio corpus and audit material are deeper than the current evidence-gated runtime.

Primary objective: compile all shards into a typed, queryable source pack with versioning, provenance, duplicate detection, schema validation and layer mapping. No archive atlas state may create diagnosis, treatment, disease inference or autonomous clinical authority.

### Full Sphere visual instrument

Historical Full Sphere outputs show lens/fold, history/NOW/forecast, antipode warnings, precession/orbital context and nested dodecahedral visual grammars that are only partially represented in current OMEGAv6.

Primary objective: recover the visual grammar as a state-bound instrument. Historical rendered videos are presentation evidence only; they do not prove the equations or physical validity behind the frames.

### Scientific domain packs

Atomic/periodic, AMO, condensed matter, universal math and Earth/space-motion workbooks should become independently loadable, typed domain packs rather than generic mode metadata.

Primary objective: preserve source/reference science separately from OMEGA-derived transforms and require unit/source checks before runtime admission.

### Installer / reconstruction

The compact installer archive already includes hashes, manifests, BAT/PowerShell install paths and reconstruction tooling.

Primary objective: compare against the current Hybrid/native packaging path and recover only stronger repair, preflight, rollback and support-bundle mechanics.

### Release/provenance history

B015 manifests, continuity records, test receipts and B058 correspondence material can teach the Archive Compiler the difference between `DESIGNED`, `BUILT`, `TESTED`, `ACCEPTED`, `DEPLOYED`, `SUPERSEDED` and `CURRENT`.

Primary objective: create a release-lineage graph and carry historical rationale as scars/provenance without treating old receipts as current live proof.

## Dependency admission boundary

Two newly reviewed archive strata are clearly dependency-oriented:

- the optics folder contains recognizable SymPy optics source for ray-transfer matrices, Gaussian beam parameters, lenses, refraction, mirrors and related calculations;
- the Qt runtime tree contains Quick3D/XR/particle/material/lightmap and spatial-audio runtime assets.

These may be useful dependencies, but they must retain exact origin/version/license identity. They are not OMEGA-original inventions and their presence does not prove OMEGA currently executes those capabilities.

## Solver implication

If origin/license/version checks pass, the optical workflow can gain an attributed analytical stage:

`symbolic/paraxial analytic check → OMEGA fast screening → RCWA → FDTD`

The analytic stage is useful for ABCD/Gaussian/geometric cross-checks. It is not a substitute for full-wave validation.

## Definition of completion

R288 is not complete merely because artifacts are listed. A family becomes promotion-ready only when:

1. its source files/packages have been fingerprinted;
2. origin and licensing are known;
3. archive semantics are mapped to current OMEGAv6 contracts;
4. unique capability delta is explicit;
5. competing/superseded authority is removed;
6. deterministic tests or evidence gates exist;
7. desktop/mobile/operator surfaces are wired where applicable;
8. proof receipts bind the exact candidate;
9. promotion preserves current truth and authorization boundaries;
10. the successor state is written back to the archive ledger.

R288 therefore treats the Drive archive as a continuing development corpus, not as automatic authority.
