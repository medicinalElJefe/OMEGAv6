# OMEGA R503 — Calculus-Native Autonomous Development

R503 makes calculus inheritance an admission condition for autonomous source work. It does not create a new Canon owner, source-promotion authority, deployment writer, truth class, physical primitive, or physical dimension.

## Problem closed

A worker that can edit code but cannot reconstruct OMEGA's authority, capability lineage, developmental continuity, scars, vetoes, and proof boundaries can automate incoherent repair loops. R503 therefore separates **worker qualification** from **worker execution**.

## Cold-start packet

Every governed autonomous mutation path receives an exact-base packet derived from the existing authorities:

- R474 Year-Corpus Capability Graph: capability lineage, 12-pillar architecture, strongest-valid selection, conservation, presentation non-authority.
- R457 Heightened Mode: developmental sequence as the object of analysis; growth/transport/acceleration/jerk/curvature/scar/future-cone law; STAY/TURN/ESCALATE; no physical-dimension inflation.
- R245/R170: governed self-build, residual policy, one-candidate fence and bounded generation.
- R164: returned residual evidence.
- R240: exact source promotion.
- R142: execution receipts.
- R125: sole CanonState admission.
- `ci.yml`: sole production deployment writer.

The packet is bound to the exact base SHA. Chat history is not required for admission.

## Worker literacy gate

A worker must reconstruct the authority boundary and developmental law before mutation. The attestation must bind the exact packet context, identify the residual evidence, name at least two admissible alternatives, preserve PRUNE → TRANSLATE → PROVE and STAY/TURN/ESCALATE, state a bounded developmental delta, and assert all vetoes.

R170 is deterministic rather than model-reasoned, so its attestation is a structural cold-start qualification for the bounded capsule selector. CLOUD-01's AI repair path is a reasoning worker and must return its own `REASONING_DEVELOPER` attestation. The R503 validator rejects an otherwise syntactically valid patch if that reconstruction is missing or wrong.

## Developmental delta

The delta is explicitly non-Canonical planning evidence:

`ΔΩ = capability + coherence + autonomy + usability + recoverability − regression − duplication − authority fragmentation`

A positive claimed delta never proves production success. Existing exact-head CI, deployment, runtime, source, Hybrid, browser, and Canon admission boundaries remain authoritative.

## Acceptance boundary

R503 is successful only when:

1. the cold-start packet derives from the existing authority sources on the exact base;
2. R170 cannot autonomously select/generate under the governed workflow without a valid R503 admission;
3. CLOUD-01 refuses source mutation when the packet cannot be constructed;
4. a CLOUD-01 reasoning proposal is rejected unless it reconstructs the calculus/authority contract and developmental delta;
5. contradictions, rejected alternatives, residual evidence, and scars remain retained;
6. R125/R142/R164/R240/`ci.yml` retain their existing separate authorities.
