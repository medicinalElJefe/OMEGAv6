# OMEGA R152 — Adaptive Sovereign Build Missions

R152 converts the R151 authenticated PC build surface from a one-cycle durable mission admission into a bounded returned-proof lifecycle.

Execution path:

`CURRENT AUTHENTICATED HEARTBEAT -> DISCOVERY -> PROJECT PROOF -> NODE PREFLIGHT WHEN REQUIRED -> BUILD/TEST -> RETURNED FAILURE EVIDENCE -> BOUNDED READ PREIMAGE -> EXACT SHA-BOUND PATCH PROPOSAL -> REBUILD/RETEST -> PACKAGE + SUPPORT BUNDLE -> COMPLETE`

Core laws:

- No queue state, browser state, or model output is execution proof.
- Only the authenticated R132 host can perform the allow-listed native operations inside the approved root.
- Broad-root runs discover before mutation.
- Node projects prove declared build/check/test scripts before adaptive continuation.
- Repairs can target only source paths named by returned failure evidence.
- Every mutation is exact-replacement and bound to the SHA-256 of a returned READ_TEXT preimage.
- Workers AI may propose a patch but cannot bypass path, preimage, replacement-count, operation-envelope, device-capability, or cycle validation.
- The mission has a 12-cycle hard cap and at most two repair attempts. This is enough for discovery, preflight, two bounded repair loops and final packaging while remaining non-autonomous outside the approved envelope.
- PACKAGE and SUPPORT_BUNDLE occur only after a returned successful build/test cycle.
- COMPLETE is written only after the package job itself returns successfully.
- R141 remains returned Hybrid proof closure, R147 remains unified executor evidence, and R125 remains CanonState admission authority.
- R152 extends the existing R116 Durable Object; it does not create a shadow Worker or a second canonical runtime.

The production UI remains the R151 Sovereign full-build surface. The R152 Worker layer upgrades what happens after each host return without invalidating the established connection or requiring the PC to be paired again.
