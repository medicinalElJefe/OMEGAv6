# R266 — Adaptive Coherence Cycle

R266 makes the R265 cycle persistent across bounded software iterations without turning coherence into authority or scientific truth.

## Why R266 exists

R265 established the cross-skin operator and made Water Geometry, Woven Continuity, Violet re-expression, frame/resolution relativity, scar, orientation and provenance executable. The next limitation was temporal: most callers compiled a strong present-state envelope but did not systematically feed the proved carry into the next computation.

R266 closes that gap:

`OBSERVE → WATER_TRANSPORT → WOVEN_PATH → VIOLET_REEXPRESSION → PROVE → CARRY → RECONTEXTUALIZE → ADAPT_NEXT_CONTEXT`

The final step is deliberately bounded. R266 may tune software context from actual history; it does not rewrite evidence, mutate CanonState, promote source, or claim foundation-model training.

## Admissible learning evidence

Only three history classes can calibrate a later cycle:

- `EXPLICIT_OPERATOR_OUTCOME`
- `OBSERVED_TRANSITION`
- `RETURNED_PROOF`

Unknown, inferred, unchosen or merely available alternatives do not become negative training examples. This preserves the R265 rule that an unchosen candidate is not silently a failure.

History is capped at 64 entries. Confidence grows only with admissible samples and reaches the configured full-confidence ceiling at 12 samples. Calibration is capped to ±0.08, so history can guide a cycle but cannot overwhelm the current source-backed state.

**Cold start is exactly R265.** With no admissible history, calibration delta is zero and adaptive coherence, future-preservation and Water-memory remain the R265 values.

## Carry and recontextualization

R266 carries:

- current R265 computation coherence;
- explicit/observed/returned outcome history;
- scar and residual memory;
- Water memory context;
- measured round-trip and commutation residuals when present;
- provenance classes;
- bounded trend.

The resulting `nextContext` is an input to a later planning, learning, rendering or self-build evaluation. It is not a command and not a source mutation.

## Sparse dimensional-relativity bridge

R266 adds a sparse address projection across the declared resolution ladder:

`12 → 144 → 1,728 → 20,736 → 248,832`

Projection maps a source address through normalized cell position to the destination resolution. The bridge computes an actual software round-trip residual by projecting back. This avoids enumerating the full atlas and provides a concrete consistency measurement for resolution changes.

The residual measures the software projection only. It is not a physical error measurement and the address levels remain representational unless independently calibrated to an empirical model.
