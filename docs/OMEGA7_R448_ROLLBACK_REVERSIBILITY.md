# R448 · OMEGA7 Rollback / Reversibility Proof

R448 proves that OMEGA7 remains a reversible successor rather than a destructive replacement.

## Browser journey

The exact built-product browser proof:

1. seeds a known canonical OMEGA address;
2. enters OMEGA7;
3. opens a native traversal route;
4. verifies the canonical address remains unchanged;
5. uses the explicit OMEGA6 rollback control;
6. requires the accepted OMEGAv6 product surface to return;
7. verifies the canonical address still matches;
8. verifies persistent OMEGA7 opt-in is cleared;
9. re-enters OMEGA7 through the explicit URL;
10. verifies canonical address continuity again.

## What rollback means

Rollback changes presentation/product shell.

It does not rewrite CanonState, erase the address lineage, or silently migrate state into a different authority.

The accepted OMEGAv6 presentation remains available throughout the OMEGA7 parity phase.

## Retirement boundary

Even after R448 passes, legacy retirement remains a separate governed decision.

R448 only proves that the current successor path is reversible and does not strand the user inside OMEGA7.
