# OMEGA R268 System Foundry

R268 promotes OMEGA from a collection of specialist surfaces toward a reusable governed system-construction substrate without replacing accepted production behavior.

## Construction grammar

A system genome declares identity, capabilities, goals, interface lenses and evolution objectives. The compiler resolves dependency closure into an active frontier, retains unused capabilities as dormant/addressable registry entries, derives a shared operator DAG, selects only evidence-admissible executors, records blockers, and emits proof obligations.

This is declarative planning. R268 does not execute arbitrary code, mutate CanonState, dispatch around R147, replace R205, bypass R239, promote source around R240, convert R243 planning into execution-motion truth, or create a second production writer.

## Eight layers

- STATE — identity and declared system state.
- INTELLIGENCE — bounded reasoning over typed state and proof.
- MEMORY — continuity, invariant carry and scar/history carry.
- RELATION — typed graph/index representation.
- COMPUTATION — dependency resolution, operator DAG and active frontier.
- ACTION — governed action requests only.
- OBSERVATION — source/provenance binding.
- PROOF — fail-closed proof obligations and admission boundaries.

## Woven Continuity as software mechanics

R268 represents Woven Continuity as a reusable software operator sequence:

`partition -> transform/exchange -> invariant carry -> scar/history carry -> re-contextualize`

It is not a new physical primitive and does not turn atlas resolution levels into literal physical dimensions.

## Authority taxonomy

R268 keeps distinct roles rather than overloading the word canonical:

- Sovereign canon authority: accepted sovereign lineage / Drive release pointer remains independently governed by existing contracts.
- Source authority: exact Git commit SHA.
- Deployment authority: `.github/workflows/ci.yml` only.
- Runtime authority: exact deployed SHA plus live acceptance plus receipt.
- Device authority: current authenticated heartbeat only.
- CanonState admission: R125 only.

Inherited boundaries remain mandatory: R141 exact return, R146 history, R147 dispatch, immutable R205 executor semantics, R239 resource governance, R240 exact-head promotion, and R243 planning/execution-motion truth separation.

## Performance model

R268 does not materialize the full capability universe for every task. It computes dependency closure for the selected genome, creating an active frontier and leaving the rest dormant. Operators are indexed into one DAG so common operators can be shared rather than executed once per named mode or UI lens. Interface lenses read shared state/results and do not redefine state.

Abstract cost and latency values are planning signals only; they are not claims of measured wall-clock performance.

## Initial genomes

- `omega.self` — self-model of current OMEGA. It explicitly does not claim legacy migration into generated form is complete.
- `collections.workbench` — account/history/work-queue planning substrate.
- `sar.lab` — evidence-bound acquisition/reconstruction/provenance substrate.
- `science.lab` — hypothesis/observation/residual reasoning substrate.
- `software.factory` — requirement/candidate/proof/promotion substrate.

These genomes demonstrate reuse of one kernel/compiler rather than creating five independent application architectures.

## Evidence placement

`DEVICE` placement requires a current authenticated device heartbeat. CI, browser state and synthetic transport are insufficient. `EXTERNAL` placement requires a real external binding. Missing evidence returns `DEVICE_PROOF_REQUIRED` or `EXTERNAL_DEGRADED` and does not fabricate success. Cloud/browser-capable work can remain active independently when its own requirements are satisfied.

## Adoption sequence

R268 is the foundation and first live instrument. Existing specialist implementations remain accepted donors/capabilities. Future governed releases can progressively register existing OMEGA functions behind typed capability descriptors, connect real R239 resource snapshots, expose generated lenses, measure operator reuse and latency, and eventually compile larger portions of OMEGA from the self genome. Migration must remain parity-tested and no-regression-by-omission compliant.
