# R356 — Coherent Product Design Convergence

## Purpose

R355 proved monotonic software/runtime continuity, but the human interface still reflected years of additive restoration layers. R356 changes presentation ownership without reducing capability authority.

The R356 law is:

`one canonical route authority → one product frame → one active instrument → contextual secondary instrumentation → explicit proof/history disclosure`

R356 does not remove the 44-route universe, capability authority, specialist engines, proof surfaces, restored execution bodies, Hybrid authority, Canon admission, or production writer.

## Product ownership

The normal workstation path now has one outer product frame:

- one route header
- one canonical state ribbon
- one primary instrument region
- one bounded context rail
- one optional workflow drawer
- one persistent canonical navigator

The old ready-state workstation topbar no longer competes with the route header. R81 SurfaceIntegrity remains the containment/proof membrane inside the product frame.

## Visual grammar

`omegaProductFrameR356.css` is the final global presentation authority for product chrome. Older styles remain available as module-local compatibility styling for specialist instruments, but no longer define the outer product geometry.

The shared design grammar covers:

- Home
- global navigator
- workstation route frame
- state/context presentation
- nested specialist modules
- Convergence organization
- desktop/mobile responsive ownership

## Secondary instrumentation

R94 provenance and R107 calculus fabric remain present and inspectable. R138 capability topology remains fully operational, but is contextual rather than automatically consuming the top of every specialist surface.

Projection remains distinct from admission. Route remains distinct from execution. R125/R141/R146/R147 and ci.yml retain their existing authorities.
